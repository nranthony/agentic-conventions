# ADR-0009: `validation/` — an opt-in tier for measured-behaviour evidence

- Status: Accepted
- Date: 2026-08-12
- Deciders: nranthony + agent
- Distilled from: `work/0010-validation-evidence/proposal.md`

## Context

A repo with a measurement harness produces an artifact the existing tiers cannot hold: a
committed record of how the system performed against a labelled corpus, which a CI gate reads
by path.

Each tier rejects it for a different reason. `docs/` is prose canon and this is a machine-read
blob. `tests/` holds executable checks and this is an *input* to a check. `docs/adr/` records
decisions and a measurement is not one. `work/` is the closest fit and the most decisively
wrong: its exit rule (ADR-0006) archives an item when the work resolves, and **an artifact a
build depends on can never be archived.**

The missing category is *evidence* — a dated record of measured behaviour, committed
deliberately, superseded by regeneration rather than edited. It is adjacent to an ADR in
spirit: both record a moment. ADRs record what was decided; this records what was measured.

Two forces made it worth settling now rather than per repo:

- **It multiplies.** The originating repo has one corpus pinned, a second with numbers worth
  pinning, a third arriving, and every algorithm version bump wants a before/after pair. The
  convention is free at one file and a migration at ten.
- **A single file that is both record and gate authority is a trap.** Regenerating it moves
  the goalposts, and the diff reads as routine churn: a run that drops two points of
  sensitivity produces a green build and a plausible commit.

## Decision

**1. A new opt-in tier, `validation/`, organised by corpus.**

```
validation/
├── README.md
└── <corpus>/
    ├── expected.json    # hand-edited. The gate's authority. Never machine-written.
    ├── measured.json    # regenerated. The record of the last run. Never hand-edited.
    └── measured.md      # regenerated by the same command. The human-readable table.
```

A corpus is the unit a reader asks about and the unit that changes independently. Where one
corpus carries several independent harnesses, nest one level: `<corpus>/<harness>/`.

**2. Authority is encoded in the filename, and the names are fixed across repos.**

- Nothing regenerates `expected.json`. A regeneration script that writes it is a bug.
- Nobody hand-edits `measured.*`. A hand-edit there falsifies a record.

A reader entering an unfamiliar repo must be able to tell authority from record without
opening either file, which rules out repo-specific names. The originating repo's
`beat_truth.json` fails twice over: it says nothing about which of the two roles it plays, and
"truth" conventionally names the *reference labels* rather than a measurement against them.

**3. Both files are JSON, and every threshold carries a required `why`.**

```json
{ "sensitivity": { "min": 0.995, "why": "floor agreed in ADR-00XX; record 207's flutter run binds it" } }
```

The justification must sit beside the number — a threshold with no stated reason is precisely
what gets loosened silently later. TOML was chosen first, for comments, and reversed: JSON is
readable by any gate in any language with no dependency, and under this project's standing
dependency rule "add a TOML parser" is a stop-and-ask rather than a detail. A `why` **field**
also beats a comment on its own merits — it can be required, it can be validated, and a gate
can quote it in the failure message.

**4. Records carry provenance.** `measured.json` opens with a `provenance` block; `measured.md`
repeats it as a header. `command` and `corpus` are required — the end state for an
un-regenerable record is folklore, and a number without its corpus version is not comparable.
`corpus_digest` is required where a corpus has no authoritative version identifier, and may
lag where it has one, since the version string already separates a data change from a
regression and the digest then guards only local corruption.

**5. `measured.md` is required and written by the same command as the JSON.** With no
enforcement layer, the readable table is the only way anyone checks a claim without running
the harness. Generating the pair separately is how they drift.

**6. `validation/README.md` is the tier's index and carries the rules** — what the folder is,
the two authority rules verbatim, one row per corpus (what is measured, which gate reads it,
the exact regeneration command), how to add a corpus, and what does not belong. The *how the
harness works* write-up stays in `docs/`.

**7. Scope: ground-truth accuracy evidence only.** Golden-output snapshots stay in `tests/`;
ground-truth labels are input data and stay with the corpus; performance benchmarks are
environment-dependent and have no home yet; external reports and scan baselines are excluded
because they are not regenerable from the repo, so decisions 2 and 4 cannot apply.

**8. Named `validation/`, not `qa/`.** IEC 62304 / ISO 13485 expect *requirement → verification
protocol → verification record*, and this tree is shaped like the third. Adopting the
vocabulary costs nothing now and saves a rename if a safety-case question ever resolves toward
"this software is an owned control." **This is a naming choice and makes no compliance claim** —
it declines to fight the vocabulary later, it does not assert a process.

**9. Enforcement is deferred, with triggers.** No CI check and no `CODEOWNERS` requirement ship.
It becomes worth adding when either fires: **a second person commits to `validation/`**, or **a
threshold moves without a `why` updated beside it**. The candidate mechanisms are a
`CODEOWNERS` entry on `validation/*/expected.json` (targets the goalpost move, the common case)
and a check flagging a `measured.*` diff whose `provenance.commit` did not change (targets a
falsified record, rarer).

## Consequences

- **The claim is legibility, not prevention, and the tier says so.** The split removes one
  path — regenerating a record can no longer change what passes, because the gate reads a
  different file. What remains is a hand-edit to `expected.json`: a one-line diff to a named
  file with a required justification beside it. Nothing stops it; it can no longer happen
  invisibly. Overstating this would be the drift these records exist to catch.
- **Adopting the tier forces a question no one has had to answer**: which measured numbers the
  gate fails on, versus which are recorded for a reader. One file doing both jobs never posed
  it. Asked once at one corpus this is cheap; asked retroactively across several it is several
  after-the-fact judgements — which is why the originating repo adopts at its single corpus
  rather than waiting for the plugin round trip.
- **Unproven until that adoption**: whether the enforced-versus-recorded line is obvious in
  practice. If most repos find nearly every number wants enforcing, `expected.json` stops being
  small and the justification-per-threshold discipline gets expensive. That would not
  invalidate the split, but it would want a follow-up on how much detail belongs in the
  authority file.
- **JSON has no comment syntax**, so someone will eventually try `//` and break the file. The
  required `why` field is the sanctioned place and the template says so.
- **A repo whose gate cannot parse JSON does not exist in practice**, which is the point of the
  reversal — but a gate that wants TOML ergonomics no longer gets them.
- This repo will never carry a `validation/` tier itself: it ships no measurable behaviour. The
  template is the only artifact here, the usual state for the opt-in tiers.
- No size ceiling is set. `measured.json` must stay reviewable **as a diff**; past that point
  the record holds aggregates and the harness regenerates per-record detail on demand.

## Alternatives considered

- **`tests/baselines/`** — the standard golden-file convention, cheapest, no new top-level
  directory, beside its consumer. Rejected: it buries validation evidence in the test tree
  where a collaborator auditing an accuracy claim will not look, and the human-readable table
  is a document rather than a fixture.
- **`docs/validation/`** — has precedent, since generated test-gated references already live
  under `docs/` in the originating repo. Rejected: `docs/` is prose canon and a machine-read
  gate input sits oddly in it.
- **`reports/` at root** — the usual name for generated output, and exactly the problem: it
  reads as gitignorable scratch, while these files are committed deliberately.
- **`work/`** — rejected on the exit rule; see Context.
- **`qa/`** — the honest, unloaded word, and a live option if the regulated vocabulary is ever
  judged misleading. Lost to the rename-cost argument in decision 8.
- **One file, gate reads the record directly** — simplest, no duplication. Rejected: it makes
  every regeneration a potential silent goalpost move.
- **TOML for `expected.*`** — chosen first and reversed; see decision 3. Comments are its only
  advantage over JSON here, and a required field delivers the same property with better
  tooling behaviour and no dependency.
- **Shipping the enforcement check with the tier** — rejected for now: CI complexity is not
  wanted during active development, and `CODEOWNERS` is overhead in a solo repo by the
  blueprint's own reckoning. Deferred with triggers rather than dropped, and deliberately not
  opened as a `work/` item — an item nobody is working cannot satisfy `work/`'s exit rule, so
  it would sit in the tree as precisely the stale artifact that rule exists to prevent.
